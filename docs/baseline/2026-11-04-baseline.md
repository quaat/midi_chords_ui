reimplementation started. Findings come from reading the code and running the test suite through an
offline harness; the dev server and production build were **not** exercised in this environment because
`node_modules` could not be installed (the npm registry was unreachable through the sandbox proxy).

## Preserved behaviours (compatibility fixtures)

These behaviours are retained and covered by the existing tests, which keep running unchanged:

- Chord text format: one event per line, `<symbol> [| measures]`, `#` comments, blank lines ignored,
  `NC` / `N.C.` rests, fractional measures, default measure length (`test/parser.test.ts`, `test/smoke.test.ts`).
- Chord symbol vocabulary documented in the README (`test/theory.test.ts`).
- Chord Pathways: six deterministic modes, duration splitting, turnaround append (`test/pathways.test.ts`).
- Arpeggiation math (`test/arpeggiation.test.ts`).
- MusicXML generation and OSMD cursor measure mapping (`test/musicxml.test.ts`, `test/sheetMusicCursor.test.ts`).
- Web MIDI output retrigger regression: an older note-off must never silence a newer note-on of the
  same pitch (`test/webMidiEngine.test.ts`).
- Single-track SMF export header and timing (`test/smoke.test.ts`).
